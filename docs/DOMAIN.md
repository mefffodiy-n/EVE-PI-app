# Игровая механика — что известно точно, а что нет

Вынесено из `CLAUDE.md` (16.09.2026, по образцу `docs/DOMAIN.md` в
github.com/Alexmidrus/EveGAS_calc): это справочник по игровым фактам и
допущениям, а не по устройству кода — `CLAUDE.md` остаётся про правила
разработки и структуру репозитория, здесь — про саму EVE Online.

## Что известно точно, а что нет

**Проверено по четырём источникам** (шаблоны DalShooth —
<https://github.com/DalShooth/EVE_PI_Templates>, их README,
eve-webtools.com, вики EVE University): рецепты и количества, стоимости
структур, ёмкость командных центров, длительности циклов, модель линков
`L = 0.012·radius + 1`, `cpu = 15 + 0.2·L`, `pg = 10 + 0.15·L`.

**Не подтверждено, помечено в `data/pi_reference.json` → `assumptions`:**

- **Число планет на персонажа** — принято `Interplanetary Consolidation + 1`.
  Единственное непроверенное число в самом расчёте. Возвращается в ответе
  `/api/calculate` в поле `assumptions`.
- **Стоимость второго причала** — README даёт 3600 CPU за один и 5200 за два,
  хотя 2×3600 = 7200. Взято консервативное 7200. Решает, применим ли двойной
  P4-шаблон на планетах крупнее 9 600 км (иначе предел 61 700). Проверяется
  постановкой двух P4-шаблонов на планету ~20 000 км при CCU V.
- **Компоновка прямого P2** — готового шаблона в источнике нет, состав
  посчитан из стоимостей структур. Сами стоимости проверены.
- **Плотность сырья считается постоянной.** В игре месторождения истощаются,
  живых данных нет. Есть множитель `extraction_margin`, но это поправка,
  а не расчёт.

## Механики игры, важные для расчёта

- Один персонаж — одна колония на планету. **Разные** персонажи могут ставить
  колонии на одну планету без ограничений, поэтому нехватка планет не является
  ограничением: упирается всё в число персонажей.
- Два шаблона на планету требуют Command Center Upgrades V.
- Добывающий шаблон (00) требует CCU IV: при III он перегружает PG на планете
  любого размера. Это расчётный вывод, в источнике его нет.
- P4 ставится только на Barren и Temperate — правило игры. Для P2/P3 это наше
  предпочтение (мельче планета — дешевле линки), и при нехватке таких планет
  P2/P3 размещаются на других типах с предупреждением.
- Используются только шаблоны варианта 00; LS пропускаются при загрузке.

## Где это используется в коде

- `data/pi_reference.json` — структуры, ёмкость CC, модель линков, поле
  `assumptions` для непроверенных чисел.
- `domain/capacity.py` — CPU/PG против лимита CC, модель линков.
- `domain/templates.py` — разбор игровых JSON-шаблонов застройки
  (правило 2 в `CLAUDE.md`: при расхождении с названиями побеждают
  `type_id` из шаблонов).
- `domain/planets.py` — данные о планетах: сырьё, радиус, регионы.
