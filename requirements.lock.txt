#
# `requirements.txt` описывает НАМЕРЕНИЕ совместимости (>=, границы
# снизу) — им пользуется человек, читающий требования проекта. Этот файл
# описывает то, что РЕАЛЬНО ставится: `pip install -r requirements.lock.txt`
# вместо requirements.txt даёт одинаковый набор версий что на разработке
# (Windows), что на проде (Ubuntu) — без этого `pip install -r
# requirements.txt` в разное время мог бы подтянуть разные
# минорные/патч-версии, и окружения молча разошлись бы.
#
# Источник — объединение `pip freeze --local` дев-venv (Windows) и
# прод-venv (Ubuntu, 16.09.2026): все пересекающиеся пакеты совпали
# версия в версию, поэтому список один на оба окружения, без platform-
# маркеров. Пакеты, специфичные одному окружению — psycopg/psycopg-
# binary (только прод: PI_DATABASE_URL=postgresql+psycopg://..., на
# dev с SQLite ни один код их не импортирует), colorama и tzdata
# (транзитивные зависимости click/pandas на Windows) — ставятся без
# вреда и на другом окружении (чистый Python, платформенных условий не
# требуют), поэтому включены в общий список, а не в отдельные файлы.
#
# Обновлять вручную: `pip freeze --local` в проверенном venv, перенести
# сюда нужные строки, прогнать полный набор тестов на обеих платформах.
# Не генерировать автоматически при каждой сборке — в этом весь смысл
# фиксации (см. requirements.txt).
