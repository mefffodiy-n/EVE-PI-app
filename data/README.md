## pi_reference.json
Справочник для расчёта CPU/PG:
- ёмкость командного центра по уровням Command Center Upgrades (0–5);
- стоимость каждой структуры (ECU, basic/advanced/high-tech фабрики,
  storage, launchpad, голова экстрактора);
- модель линков: `L = 0.012·radius + 1`, `cpu = 15 + 0.2·L`, `pg = 10 + 0.15·L`
  на один линк;
- каталог шаблонов застройки (только варианты 00);
- пропускная способность фабрик и рекомендованные скиллы;
- соответствие type_id пинов категориям структур.

**Источник:** https://github.com/DalShooth/EVE_PI_Templates — README
(раздел "Best Estimate Template PG and CPU Usage") плюс разбор самих
JSON-шаблонов. Копии шаблонов также опубликованы на
https://wiki.eveuniversity.org/PI_Templates с разрешения автора.

**Проверено:** стоимости структур сходятся со всеми 6 сводками README
точно; формула линков воспроизводит все 60 точек 5 таблиц README
с отклонением меньше 1 (округление).

Зафиксированные особенности — см. поля `_source` внутри файла:
- сводная таблица "Miner + P1 Template" в README описывает вариант **LS**,
  а не 00 (5700/9800 против 6100/10400 у 00);
- предупреждение README про перегрузку майнера выше 15 000 км не сходится
  с его же таблицами (расчёт даёт ~26 000 км для LS); на 00-шаблон
  это не влияет, он использует 10 голов вместо 16;
- в JSON-шаблонах поле называется `Diam`, в таблицах README — `Radius`;
  шкалы совпадают с колонкой `Radius [km]` в `planet_industry.csv`.

## templates/
Реальные JSON-шаблоны застройки в игровом формате, разбираются
модулем `domain/templates.py`. Файлы с ` - LS - ` в имени пропускаются
при загрузке (решение проекта — используем только 00).

Сейчас здесь лежит один образец (`Miner - 00 - Bacteria.json`) для тестов.
Полный набор нужно скачать из релизов репозитория-источника и положить сюда.

Разбор даёт: состав структур, число линков и голов экстрактора, маршруты,
схемы производства, а также позволяет подставить `CmdCtrLv` под уровень
конкретного персонажа и отдать готовый файл для импорта в игру.

## schematics.json
**Создаётся у вас локально**, в репозиторий не кладётся:

```
python -m scripts.extract_schematics --write
```

Скрипт извлекает количества «вход/выход за цикл» из маршрутов (поле `R`)
ваших шаблонов в `data/templates/`. Это единственный способ получить эти
числа из проверенного источника: в `recipes.json` есть только входы,
выходов там нет, а придумывать их нельзя.

Побочная польза: тот же скрипт строит карту «имя продукта → type_id»
(имя берётся из имени файла шаблона, type_id — из маршрута выхода
фабрики) и тем самым закрывает отсутствующий `type_ids.json` — без
единого обращения к ESI.

Скрипт заодно сверяет извлечённые составы с `recipes.json`. Расхождение
означает ошибку в одном из наборов, и лучше узнать о ней там, чем
получить неверный план.

## planet_industry.csv
**Нужно скопировать вручную** из исходного репозитория (`planet industry.csv`,
с пробелом в имени) и положить сюда под именем `planet_industry.csv`.

Почему файла нет в скелете: он на 975 строк, и через просмотр GitHub
доступна только часть — фабриковать недостающие плотности сырья нельзя.

После копирования `domain.planets.load_planets()` применит нормализацию
заголовков (`Polyramids` → `Polyaramids`, `Supertensil Plastics` →
`Supertensile Plastics`) и отфильтрует служебные строки (`max P2`, `#REF`).
