# data/

Все файлы — только для чтения из кода (`domain/`). Что где живёт и откуда взято.

## recipes.json
68 продуктов: 8×P4, 21×P3, 24×P2, 15×P1. Целостность проверена тестами —
все входы разрешаются в известные продукты или R0-сырьё. Полная сверка
с вики EVE University: ноль расхождений. `Positron Cord` удалён
(не существует), `Industrial Explosives` исправлен на Fertilizer +
Polytextiles по правилу приоритета шаблонов.

## pi_reference.json
Справочник для расчёта CPU/PG:
- ёмкость командного центра по уровням Command Center Upgrades (0–5);
- стоимость каждой структуры (ECU, basic/advanced/high-tech фабрики,
  storage, launchpad, голова экстрактора);
- модель линков: `L = 0.012·radius + 1`, `cpu = 15 + 0.2·L`, `pg = 10 + 0.15·L`
  на один линк;
- каталог шаблонов застройки (только варианты 00);
- пропускная способность фабрик и рекомендованные скиллы, включая
  `recommended_skills._type_ids` — type_id скиллов CCU (2505) и IC (2495)
  для `scripts/sync_character_skills.py`;
- соответствие type_id пинов категориям структур.

**Источник:** https://github.com/DalShooth/EVE_PI_Templates — README
(«Best Estimate Template PG and CPU Usage») плюс разбор самих JSON-шаблонов.
Копии также на https://wiki.eveuniversity.org/PI_Templates.

**Проверено:** стоимости структур сходятся со всеми 6 сводками README;
формула линков воспроизводит все 60 точек 5 таблиц с отклонением < 1.

Зафиксированные расхождения внутри источника — в полях `_source` файла:
- «Miner + P1 Template» в README описывает вариант **LS**, а не 00
  (5700/9800 против 6100/10400 у 00);
- предупреждение про перегрузку майнера выше 15 000 км не сходится
  с его же таблицами (расчёт даёт ~26 000 км для LS); на 00-шаблон
  не влияет — там 10 голов, а не 16;
- в JSON поле `Diam`, в таблицах README `Radius`; обе шкалы совпадают
  с колонкой `Radius [km]` в `planet_industry.csv`.

## type_ids.json
105 записей: продукты, сырьё, структуры и командные центры. Статический
снимок, нужен фронтенду для иконок с `images.evetech.net`. Рантайм к ESI
за ним не ходит (правило проекта 3) — собран один раз скриптами.

## templates/
68 игровых JSON-шаблонов застройки (варианты 00: 45×P2/P3, 8×P4,
15 майнеров). Разбирает `domain/templates.py`: состав структур, число
линков и голов, маршруты, схемы. Тот же модуль подставляет `CmdCtrLv`
под уровень персонажа и отдаёт файл для импорта в игру. Файлы с ` - LS - `
в имени пропускаются при загрузке.

## planet_industry.csv
968 планет региона: система, тип, радиус, налог POCO и плотности сырья
(34 R0-колонки + 24 для прямого R0→P2). `domain.planets.load_planets()`
при загрузке нормализует заголовки (`Polyramids` → `Polyaramids`,
`Supertensil` → `Supertensile`) и радиус (в исходнике разряды через
пробел), отсеивает служебные строки (`max P2`, `#REF`).

## schematics.json
**Создаётся локально, в git не хранится:**

```
python -m scripts.extract_schematics --write
```

Скрипт извлекает количества «вход/выход за цикл» из маршрутов (поле `R`)
шаблонов в `templates/` — единственный способ получить эти числа из
проверенного источника (в `recipes.json` только входы). Заодно сверяет
составы с `recipes.json` и строит карту «имя → type_id».

## pi_director.db
**SQLite dev-база, в git не хранится.** Создаётся `python -m alembic
upgrade head`, наполняется `python -m scripts.seed_dev_characters`
(только `PI_ENV=dev`). Таблицы: `characters`, `plans`, `credentials`,
`colonies`. В продакшене — Postgres через `PI_DATABASE_URL`.

## cache/, logs/, backups/
Рантайм, не код, в git нет:
- `cache/` — снимки цен и статуса сервера (сборщики), `etags.json`;
- `logs/` — журналы (`PI_LOG_DIR`), ротация;
- `backups/` — копии БД (`PI_BACKUP_DIR`, `scripts/backup.py`).

## plans/
Пусто и не используется: сохранённые планы переехали в таблицу `plans`
(Фаза 3). Каталог оставлен под старые json-файлы, если они у кого-то есть.
