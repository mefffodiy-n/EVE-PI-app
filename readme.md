# PI Director

Планировщик планетарного производства для EVE Online. Считает, сколько
колоний и каких нужно под заданные продукты, распределяет их по
персонажам и показывает, где план упирается в ограничения — число
персонажей, размер планет, уровень скиллов.

Работает на реальных данных: рецепты и стоимости сверены по четырём
источникам (шаблоны DalShooth, их README, eve-webtools.com, вики EVE
University), непроверенные числа честно помечены, а не выданы за точные
(`docs/DOMAIN.md`). Вход через EVE SSO подтягивает настоящие колонии
персонажа — что реально построено в игре, а не только расчётный план.

## Что делает

- Строит производственную цепочку P0→P4 под выбранные продукты, считает,
  сколько колоний и персонажей нужно, куда их поставить (регион,
  созвездия, домашняя система переработки).
- Подбирает планеты под переработку по радиусу и типу (P4 — только
  Barren/Temperate, правило игры), с предупреждением, если подходящих
  планет не хватает.
- Считает загрузку CPU/Power командного центра против лимита, ёмкость
  причала, стоимость линков — по проверенной модели, не оценкой на глаз.
- Оценивает выгоду в ISK на колонию-час и подсказывает, что производить
  выгоднее при равных затратах.
- Считает прогноз прибыльности в месяц с учётом налога POCO — для
  расчётного плана (доход и налог на экспорт+импорт на каждом
  перемещении по цепочке) и отдельно по факту для настоящих
  синхронизированных колоний (реальная текущая скорость выхода, налог
  только на вывоз с каждой планеты).
- Хранит и сравнивает сохранённые планы — переживают перезагрузку
  страницы и смену устройства.
- Подключается к EVE SSO: тянет реальные скиллы и колонии персонажа по
  расписанию, показывает настоящие таймеры экстракторов и честную
  проекцию состояния фабрик по маршрутам между пинами (ESI обновляет
  фабрику только при заходе в колонию в игре — дальше программа
  досчитывает сама, без выдумывания).
- Предупреждает о дефиците добычи и об истощении сырья в причале у
  перерабатывающих колоний.
- Двуязычный интерфейс (RU/EN), без сборки — один файл `web/index.html`.

Полный список — раздел «Справка» в самом приложении; список того, чего
программа **не знает** — там же, честно, а не молчанием.

## Требования

| | |
|---|---|
| Python | 3.12+ (проверено: 3.12 на проде, 3.14 в разработке; ниже не проверялось) |
| БД в разработке | ничего ставить не нужно — SQLite-файл создастся сам |
| БД на проде | PostgreSQL (единственная проверенная в бою; другие СУБД, поддерживаемые SQLAlchemy, не тестировались) |
| Зависимости | ставятся `pip install -r requirements.lock.txt` |

Docker, Node.js, npm, сборщики фронтенда — не нужны и не будут: фронтенд
— один HTML-файл без сборки, БД разворачивается `alembic upgrade head`.

## Установка

```
git clone https://github.com/mefffodiy-n/EVE-PI-app.git
cd EVE-PI-app
python -m venv .venv
.venv\Scripts\pip install -r requirements.lock.txt   # Linux/macOS: .venv/bin/pip
```

`requirements.lock.txt` — точные версии, проверенные в бою на dev и
проде (`requirements.txt` держит только нижние границы — намерение
совместимости, не то, что реально ставится).

## Первые данные

Свежий репозиторий не считает планы без нескольких разовых шагов:

```
.venv\Scripts\python -m scripts.extract_schematics --write   # data/schematics.json — количества вход/выход
.venv\Scripts\python -m alembic upgrade head                 # таблицы БД
.venv\Scripts\python -m scripts.seed_dev_characters           # dev-персонажи (только PI_ENV=dev)
```

`python -m scripts.diagnose` проверяет, что данные, БД и эндпоинты на
месте, и говорит конкретно, чего не хватает.

## Запуск

```
.venv\Scripts\python run.py
```

Откройте **http://127.0.0.1:8000/** — именно корень, Flask сам отдаёт
интерфейс из `web/`.

Правка вёрстки с Live Server (автоперезагрузка) требует CORS:

```
set PI_DEV_CORS=1 && python run.py     # Windows
PI_DEV_CORS=1 python run.py            # Linux/macOS
```

Фронтенд сам определит другой origin. **В production переменную не
выставлять.**

## Конфигурация

Профиль выбирается переменной `PI_ENV` (`dev` по умолчанию, `prod`
явно) — от него зависит, разрешён ли `seed_dev_characters` (только dev)
и какая СУБД используется по умолчанию, если `PI_DATABASE_URL` не
задан.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `PI_ENV` | нет (по умолчанию `dev`) | `dev` / `prod` — см. выше |
| `PI_DATABASE_URL` | нет | адрес БД; без неё — SQLite-файл `data/pi_director.db` в dev |
| `PI_LOG_DIR` | нет | куда писать журналы сборщиков (`infra/logging.py`) |
| `PI_BACKUP_DIR` | нет (обязательна для `scripts/backup.py` на проде) | куда класть суточные копии БД |
| `PI_DEV_CORS` | нет | `1` — разрешить CORS для Live Server (не для прода) |
| `PI_ESI_CLIENT_ID` | для входа через EVE SSO | client_id, полученный на developers.eveonline.com |
| `PI_ESI_CLIENT_SECRET` | нет | нужен только для настоящего отзыва токена на стороне CCP (`POST /v2/oauth/revoke`) — без него «Отвязать» стирает токен только локально |
| `PI_TOKEN_KEY` | для входа через EVE SSO | ключ шифрования токенов — `python -c "from infra.crypto import generate_key; print(generate_key())"` |
| `PI_ESI_CALLBACK_URL` | нет (по умолчанию `http://localhost:8000/api/auth/callback`) | адрес колбэка OAuth |
| `PI_ESI_SCOPES` | нет | список scope через пробел, если нужен не набор по умолчанию |

Без `PI_ESI_CLIENT_ID`/`PI_TOKEN_KEY` `/api/auth/*` отвечает 503,
остальное приложение работает на dev-заглушках персонажей.

## Сбор данных по расписанию

Ни один HTTP-обработчик, отдающий данные, не ходит в ESI сам — сеть
дёргают только фоновые сборщики (`CLAUDE.md`, правило 3):

| Сборщик | Интервал | Что делает |
|---|---|---|
| `refresh_server_status` | 10 мин | число игроков онлайн |
| `refresh_market_prices` | 60 мин | цены на продукцию PI (Fuzzwork) |
| `refresh_tokens` | 15 мин | продление access-токенов ESI |
| `sync_character_skills` | 6 ч | уровни PI-скиллов персонажей |
| `sync_colony_status` | 30 мин | снимок реальных колоний, таймеры экстракторов, маршруты |
| `backup` | 24 ч | копия БД и снимков кэша |

Один процесс со своим журналом:

```
.venv\Scripts\python -m scripts.scheduler
```

Если в системе уже есть планировщик заданий (cron, Task Scheduler) —
надёжнее завести отдельные задания на каждый сборщик, он это тоже
поддерживает (см. докстринг `scripts/scheduler.py`).

## Вход через EVE SSO

OAuth2 Authorization Code + PKCE, без опоры на `client_secret` в самом
flow. Полные правила работы с ESI и SSO — `docs/ESI.md`. Коротко: вход
даёт доступ к реальным колониям и скиллам персонажа, работает без входа
целиком — расчётный план не требует ни одного персонажа из игры,
только dev-заглушки или уже вошедших через SSO.

## Развёртывание

Production-запуск — `python -m scripts.serve` (waitress) вместо
`run.py`, за nginx, оба процесса (`serve` и `scheduler`) — системными
службами. Пошагово, с реальными командами для Ubuntu и Windows (NSSM) —
`deploy/README.md`.

## Ограничения

Честно и по имени, не молчанием (то же самое видно в приложении, раздел
«Справка» → «Чего программа пока не знает»):

- Плотность сырья в месторождениях считается постоянной — в игре она
  истощается, живых данных с сервера нет.
- Прямое P2 на добывающей планете приостановлено: компоновка ни разу не
  сверена в игре (`docs/ROADMAP.md`, Фаза 9).
- Налог POCO при вывозе с планеты не учитывается в таблице «Что выгоднее
  производить» (там сравниваются шаблоны, а не конкретная застройка) —
  но учтён отдельным прогнозом прибыльности и для плана, и по факту для
  настоящих колоний (`docs/ROADMAP.md`, Фаза 9).
- Прогноз прибыльности по факту не считает налог на ввоз между разными
  колониями — ESI не отдаёт связь «какая колония кормит какую».

## Планируется

Занесено в очередь, не реализуется без отдельного запроса (подробности
и ход обсуждения — `docs/ROADMAP.md`):

- **Прямое производство P0→P2 на одной планете** — код есть
  (`domain/direct_p2.py`), но выключен в интерфейсе: застройка не
  выписана из проверенного игрового шаблона (такого шаблона в наборе
  DalShooth нет), а посчитана из стоимостей отдельных структур и ни
  разу не сверена в игре. Включение — это проверка в игре, не
  разработка с нуля.
- **Мультирегиональность** — тоже уже поддержана кодом
  (`domain/planets.py::regions()`, группировка по колонке `Region`),
  но `data/planet_industry.csv` описывает только один регион. Ни ESI,
  ни SDE плотность сырья по планетам не отдают (проверено 16.09.2026) —
  нужна такая же ручная выгрузка по каждому следующему региону, каким
  был получен нынешний файл.
- **План и выгода только по переработке из закупаемого P1** — не
  строить добывающие колонии вовсе, а считать план и прибыльность в
  предположении, что P1 покупается на бирже (по цене продавца, она уже
  собирается `refresh_market_prices.py`, но пока не отдаётся наружу), а
  строятся только перерабатывающие колонии P2→P4. Новая фича, требует
  доработки `domain/throughput.py` (остановить разворот дерева на P1) и
  `domain/poco_tax.py` (налог на ввоз купленного сырья вместо своего).
