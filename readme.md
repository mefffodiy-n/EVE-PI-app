# PI Director v2 — скелет проекта (Фаза 1)

Скелет структуры из `roadmap.md` для Фазы 1 — «Фундамент (без ESI вообще)».

## Правила проекта, зашитые в архитектуру

1. **Только проверенные источники.** Все числовые константы происходят из
   разобранных JSON-шаблонов, `data/pi_reference.json` и сверок с внешними
   источниками. Ничего не додумано; спорные места помечены в `_source`
   и `assumptions`.
2. **Приоритет источников при расхождении состава продукта:** побеждает
   JSON-шаблон застройки — его маршруты ссылаются на игровые `type_id`,
   а не на названия. Названия при этом проверяются по всем источникам,
   поскольку опечатки встречаются везде (`Chiral Stuctures` в именах
   файлов шаблонов, `Plyaramids` и `Pasmoids` на eve-webtools).
   При сомнениях — поиск по внешним источникам.
3. **Минимум обращений к ESI, и никогда — по действию пользователя.**
   HTTP-слой (`api/`) не содержит ни одного внешнего вызова. Всё, что
   требует сети, живёт в `workers/` и запускается по расписанию (Фазы 2–3).
4. **Flask, не FastAPI.**
5. **Никакого Docker.** Обычное WSGI-приложение за nginx.
6. **Не нагружать сервер при большом числе пользователей** — см. ниже.


7. **Справка и «О проекте» обновляются вместе с приложением.** После любого
   изменения функциональности, версии или данных эти разделы правятся в том
   же заходе, а не «потом». Правило исполняемое, а не декларативное:

   - реестр возможностей лежит в `domain/features.py`;
   - `tests/test_docs.py` проверяет, что каждая запись реестра упомянута
     в справке **на обоих языках**, что число заголовков в русской и
     английской версиях совпадает, что версия берётся из `version.py`
     через `/api/meta`, а не вписана в текст, и что раздел «чего программа
     не знает» на месте;
   - забыть можно, пройти мимо падающего теста — нет.

   Порядок при добавлении возможности: код → запись в `domain/features.py`
   → текст в справке на двух языках → тест зелёный. Если тест упал,
   правьте справку, а не реестр: реестр описывает то, что приложение
   действительно умеет.

## Запуск

```
pip install -r requirements.txt
python run.py
```
Затем откройте **http://127.0.0.1:8000/** — именно корень, не
`/web/index.html`. Flask сам отдаёт интерфейс.

**Частая ошибка:** открыть страницу через Live Server VS Code
(`127.0.0.1:5500/web/index.html`). Live Server отдаёт HTML, но про `/api`
ничего не знает и возвращает страницу 404 — фронтенд пытается разобрать
её как JSON и падает с `Unexpected token '<'`, а списки остаются пустыми.

Если Live Server всё же нужен (удобна автоперезагрузка при правке
вёрстки), запустите сервер с разрешённым CORS:
```
set PI_DEV_CORS=1 && python run.py     # Windows
PI_DEV_CORS=1 python run.py            # Linux/macOS
```
Фронтенд сам определит, что открыт с другого порта, и обратится к Flask
напрямую. **В production переменную не выставлять**: разрешение
принимать запросы с любого origin в бою — дыра, а не удобство.

Production (Docker не используется):
```
# Windows
waitress-serve --host=127.0.0.1 --port=8000 api:app
# Linux
gunicorn -w 4 -b 127.0.0.1:8000 api:app
```
Статику (`web/`) в production лучше отдавать через nginx напрямую,
минуя Python.

## Производительность интерфейса

Смена темы меняет CSS-переменные на `body`, из-за чего браузер обязан
пересчитать стиль всего поддерева. Каждый элемент с `transition` на цвете
при этом запускал собственную анимацию на 300 мс — в детальном виде
получались сотни одновременных анимаций, и тема «перетекала» от элемента
к элементу. Что сделано:

- на время переключения переходы глушатся классом `theme-switching`,
  и смена темы становится одной перерисовкой вместо каскада анимаций;
- строки плана помечены `content-visibility: auto` — браузер не
  рендерит те, что за пределами экрана, что снимает основную часть
  работы при пересчёте стилей на длинных планах;
- `transition: all` в базовых классах заменён на перечисление конкретных
  свойств: `all` анимирует в том числе влияющие на раскладку;
- бесконечное вращение колец отключается при системной настройке
  `prefers-reduced-motion`.

Смена фреймворка (React, Vue) этих проблем не решает: узкое место —
пересчёт стилей и переходы в самом браузере, а не обновление DOM.

## Как снижается нагрузка

Flask синхронный: пока обработчик считает, воркер не обслуживает других.
Поэтому:

- **Справочники считаются один раз на процесс** (`lru_cache`) и отдаются
  с **ETag** — на повторный запрос сервер возвращает 304 и не формирует
  тело вообще. Это самый дешёвый уровень.
- **Расчёт плана кэшируется по параметрам** (`api/cache.py`): он
  детерминирован, а набор возможных комбинаций ограничен справочником.
  Расчёт идёт вне блокировки, чтобы один долгий запрос не блокировал
  остальных.
- **Жёсткие лимиты на размер запроса**: не больше 20 целевых продуктов
  на расчёт и 500 строк на экспорт — иначе один запрос занял бы воркер
  надолго.
- **Тяжёлые pandas-операции не повторяются**: CSV читается и очищается
  один раз.

Кэш живёт в памяти одного процесса — при нескольких воркерах каждый
прогревается сам. Это осознанный компромисс: он ничего не стоит и не
требует Redis. Выносить в Redis стоит только после того, как нагрузка
подтвердится измерением.

## Как использовать этот архив

1. Распакуйте поверх текущего репозитория `EVE-PI-app`.
2. Скопируйте `planet industry.csv` в `data/planet_industry.csv`
   (см. `data/README.md`).
3. Положите полный набор 00-шаблонов в `data/templates/`.
4. Сформируйте данные о производительности:
   `python -m scripts.extract_schematics --write`
   (числа берутся из ваших шаблонов, обращений к ESI нет).
5. Удалите из репозитория `__pycache__/`, `pi_director.db` и старый
   `miner_p1.json` — последний содержит неверные числа.
6. `pip install -r requirements.txt`, затем `python run.py`

## Что реализовано и проверено

- **`domain/recipes.py`** — загрузка и валидация `recipes.json`.
  69 рецептов (8×P4, 22×P3, 24×P2, 15×P1), все входы разрешаются.
- **`domain/capacity.py`** — расчёт CPU/PG: структуры шаблона + головы
  экстракторов + линки (по формуле от радиуса) против лимита командного
  центра. Проверяет ограничения: два шаблона только при CCU V,
  P4 только на Barren/Temperate.
- **`domain/templates.py`** — разбор игровых JSON-шаблонов и подстановка
  `CmdCtrLv` под уровень персонажа для выдачи файла в игру.
  Варианты LS пропускаются (решение проекта — только 00).
- **`domain/factory_site.py`** — подбор планет под переработку: только
  Barren/Temperate, по возрастанию радиуса, с предупреждением и выбором
  вместо тихого отката на одиночный шаблон.
- **`domain/planets.py`** — загрузка CSV, нормализация заголовков и
  радиуса (в исходнике разряды разделены пробелами — без очистки
  сравнения радиуса молча давали бы неверный результат).
- **`domain/throughput.py`** — производительность фабрик и разворот
  потребности до сырья. Количества берутся из схем, извлечённых из
  ваших же шаблонов; ничего не додумывается.
- **`domain/planner.py`** — распределение персонажей по планетам:
  переработка в домашней системе, добыча на планетах с нужным сырьём,
  подбор персонажа по требуемому для данной планеты уровню CCU,
  учёт слотов планет, честные сообщения о дефиците.
- **`api/`** — Flask-слой: те же маршруты, что вызывает существующий
  `web/index.html`, единый формат ошибок, ETag, лимиты, кэш.
  `/api/calculate` подключён к планировщику полностью.
- **Экспорт в Excel** — три листа («План», «Сводка», «Проверка»).
  Сводка и запас по PG считаются формулами, а не числами из Python,
  поэтому пересчитываются при ручной правке листа. Планеты с загрузкой
  от 90% подсвечены — они сломаются первыми при любом изменении.

**Проверено числами:** стоимости структур сходятся со всеми сводками
README источника; формула линков воспроизводит все 60 точек 5 таблиц;
справочник совпадает с разобранными шаблонами. Тесты: 30 в
`tests/`, прогнаны — проходят все, кроме одного намеренно падающего
(дубль `Positron Cord` в рецептах).

## Открытые вопросы

Сверено с четырьмя независимыми источниками: JSON-шаблоны DalShooth,
его же README, eve-webtools.com и вики EVE University. Полная сверка
всех 68 продуктов с вики дала ноль расхождений.

Непроверенным в расчёте осталось **одно** значение — формула числа
планет на персонажа (`Interplanetary Consolidation + 1`). Она
возвращается в ответе `/api/calculate` в поле `assumptions`.

- Стоимость второго причала: README источника даёт 3600 CPU за один и
  5200 за два, хотя 2×3600 = 7200. Взято консервативное значение.
  Решает, применим ли двойной P4-шаблон на планетах крупнее 9 600 км
  (иначе предел 61 700). Проверяется постановкой двух P4-шаблонов на
  планету ~20 000 км при CCU V.
- ~~`Positron Cord`~~ — **удалён** из `recipes.json`. Шесть независимых
  подтверждений, включая отсутствие в списке P3 на вики EVE University.
- ~~`Industrial Explosives`~~ — **исправлен** на Fertilizer + Polytextiles
  по правилу приоритета шаблонов; подтверждено вики и диаграммами PI.
